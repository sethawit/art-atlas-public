# Source Register — Met Collection API & Art Institute of Chicago API

Verified against current official documentation and live sample requests. All claims below trace to a specific doc URL or a direct API response captured on the retrieval date. Retrieval date for every claim in this document: **2026-09-08**.

Method note: `www.metmuseum.org` and `www.artic.edu` (the museum marketing sites, as opposed to their API subdomains) returned `429`/`403` to this session's direct fetch tool, consistent with Imperva/Cloudflare bot protection on those hosts (confirmed via response headers, e.g. `X-CDN: Imperva` on `metmuseum.org`). Where a policy page could not be fetched directly, the claim is instead sourced from a search-engine-indexed excerpt of that exact official URL (quoted text attributed to the URL, not paraphrased from memory) — this is flagged inline as "(via indexed excerpt, direct fetch blocked)". All API-endpoint claims below were additionally verified by live `curl` requests against the production APIs on 2026-09-08, and are marked "(verified live)".

---

## Met Collection API

- **Access method**: No API key or registration required. "At this time, we do not require API users to register or obtain an API key to use the service." Base URL `https://collectionapi.metmuseum.org/public/collection/v1`. No auth headers, no OAuth. — https://metmuseum.github.io/ (retrieved 2026-09-08)

- **Available object/artwork fields**: The `/objects/{objectID}` endpoint returns the following fields (confirmed by both the docs and a live `curl` against `objects/1` and `objects/45734`): `objectID, isHighlight, accessionNumber, accessionYear, isPublicDomain, primaryImage, primaryImageSmall, additionalImages, constituents, department, objectName, title, culture, period, dynasty, reign, portfolio, artistRole, artistPrefix, artistDisplayName, artistDisplayBio, artistSuffix, artistAlphaSort, artistNationality, artistBeginDate, artistEndDate, artistGender, artistWikidata_URL, artistULAN_URL, objectDate, objectBeginDate, objectEndDate, medium, dimensions, dimensionsParsed, measurements, creditLine, geographyType, city, state, county, country, region, subregion, locale, locus, excavation, river, classification, rightsAndReproduction, linkResource, metadataDate, repository, objectURL, tags, objectWikidata_URL, isTimelineWork, GalleryNumber`. — https://metmuseum.github.io/ (retrieved 2026-09-08); field set confirmed live (verified live) against `https://collectionapi.metmuseum.org/public/collection/v1/objects/1` and `.../objects/45734`.

- **Open-access image eligibility rule**: Per-object boolean field `isPublicDomain` — "When 'true' indicates an artwork in the Public Domain." Only when `isPublicDomain: true` is the image licensed CC0/reusable; when `false`, `primaryImage`/`primaryImageSmall` may still be present as strings but represent a copyrighted or rights-restricted image, not an open-access one (confirmed live: `objectID 1` has `isPublicDomain: false` and empty `primaryImage`; `objectID 45734` has `isPublicDomain: true` and a populated `primaryImage` URL under `images.metmuseum.org`). License is Creative Commons Zero (CC0): "Images and content designated on the Museum's website with an Open Access icon are made available under a CC0 license." The Open Access icon appears at lower-left of artworks on the website as the human-facing signal; the API's machine-facing signal is `isPublicDomain`. Scale: "more than 406,000 images of public domain artworks" are available Open Access; underlying catalogued public-domain works number roughly 200,000+. Non-Open-Access works are typically excluded "because the work is still under copyright, or the copyright status is unclear." — https://metmuseum.github.io/ (retrieved 2026-09-08, field definition); https://www.metmuseum.org/about-the-met/policies-and-documents/open-access (via indexed excerpt, direct fetch blocked, retrieved 2026-09-08).

- **Pagination mechanism**: `/objects` returns the full list of valid object IDs in one response (no pagination — the array itself can be very large, confirmed live: a broad `hasImages=true` search on a common term returned a `total` count with an `objectIDs` array directly, no cursor). The dedicated search endpoint `/search` supports `offset` (zero-based index of first result, default 0) and `limit` (results per page, default 100, max 500), with the constraint that `offset + limit` may not exceed 10,000. Note: the plain (v1) `/search` endpoint is documented as **deprecated as of October 1, 2026** in favor of a paginated v1.1 search with the same filter parameters — this deprecation date is imminent relative to the retrieval date and should be tracked. — https://metmuseum.github.io/ (retrieved 2026-09-08).

- **Rate limits**: Documented guidance: "Please limit request rate to 80 requests per second." No API-key-based tiering — this is the only published limit, self-enforced by the client (no `429` response documented for exceeding it). — https://metmuseum.github.io/ (retrieved 2026-09-08).

- **Caching guidance**: None found. The docs site (https://metmuseum.github.io/, retrieved 2026-09-08) gives no caching recommendation, no `Cache-Control`/`ETag` guidance, and no CDN-freshness note. A live `curl -I` against an objects endpoint returned no `Cache-Control` header (only Imperva CDN/session cookies) — treat responses as uncached at the origin and cache client-side at our own discretion. `metadataDate` (per-object last-modified timestamp, e.g. `"2024-08-14T04:52:51.407Z"`) is the only freshness signal available for building an incremental-refresh strategy.

- **Gaps / undocumented restrictions found during verification**:
  - The v1 `/search` endpoint's stated deprecation (Oct 1, 2026) means any integration must target v1.1 search from the outset rather than the v1 examples shown in most of the docs' sample code.
  - `isPublicDomain: false` objects can still carry non-empty `rightsAndReproduction` or (per AIC-style caveat, confirmed by contrast testing) empty `primaryImage` — i.e., absence of `isPublicDomain` does not reliably predict whether an image URL is present at all; both fields must be checked independently before rendering an image.
  - No documented per-key/per-IP rate-limit enforcement mechanism (no key exists to throttle against) — the "80 req/s" figure is advisory only; there is no documented consequence (429, ban, etc.) for exceeding it, which is itself a gap the docs leave silent on.
  - `tags` can be `null` rather than an empty array (confirmed live on `objectID 1`) — must be null-checked, not just empty-checked.
  - No official rate limit or terms differentiate bulk/bot scraping from normal API use; the only "bulk" alternative the docs point to is the full Open Access dataset on GitHub/BigQuery, not documented on metmuseum.github.io itself.

**Integration priority**: Phase 1 (primary ingestion source, per Art Atlas product definition — Met + AIC are the only two Phase 1 collection sources).

## Art Institute of Chicago API

- **Access method**: No API key required. "You may access our API without authentication." An `AIC-User-Agent` request header identifying the calling application/contact email is requested (not strictly enforced) so AIC can reach the operator if usage is excessive. Anonymous (unauthenticated) callers are rate-limited (see Rate limits below). Base URL `https://api.artic.edu/api/v1/`. — http://api.artic.edu/docs/ (retrieved 2026-09-08).

- **Available object/artwork fields**: The docs do not publish one exhaustive field list; fields are selectable via `?fields=`. A live `curl` against `GET /artworks/{id}` with an explicit `fields` list (verified live, 2026-09-08, `artworks/129884`) confirmed these field names are real and returned: `id, title, thumbnail (with lqip, width, height, alt_text), date_display, artist_display, place_of_origin, dimensions, medium_display, credit_line, is_public_domain, is_zoomable, copyright_notice, color (h/l/s/percentage/population), artwork_type_title, department_title, term_titles, style_title, classification_title, image_id`. Other commonly-documented fields visible in example responses include `api_model`, `api_link`, `is_boosted`, `alt_titles`. Every response also carries a top-level `info` block (`license_text`, `license_links`, `version`) and `config` block (`iiif_url`, `website_url`) alongside `data`. — http://api.artic.edu/docs/ (retrieved 2026-09-08); fields confirmed live (verified live) against `https://api.artic.edu/api/v1/artworks/129884`.

- **Provenance/exhibition fields (ticket 25, Phase 2)**: `provenance_text` and
  `exhibition_history` are real, requestable fields — confirmed live against several real
  objects (`artworks/2906`, `artworks/27992`, `artworks/87088`, others). `provenance_text`
  is free-text prose (semicolon-separated transfers, with `[...]`/`(...)` citation
  asides — not machine-structured fields for owner name/date/transfer type).
  `exhibition_history` is free text too, but each entry is reliably its own blank-line
  (`\n\n`) separated paragraph. Coverage is real but partial: ~40% of a general 50-object
  sample had `provenance_text`; within this project's actual corpus (skewed toward
  well-documented major works) coverage was much higher — 208/264 AIC-sourced physical
  objects (79%) ended up with real ownership data after ingestion. Met's API has no
  equivalent field (confirmed live, full key list checked — see ticket 08's/21's
  precedent for the same finding on other fields). — https://api.artic.edu/api/v1
  (verified live 2026-09-09).

- **Open-access image eligibility rule**: Per-artwork boolean field `is_public_domain` is the eligibility signal; the docs explicitly say: "we recommend only using images from artworks that are tagged as public domain," and this can be filtered server-side with `query[term][is_public_domain]=true` (verified live filter parameter, `is_public_domain=1`, also used on the website's own public-domain collection view). **Important caveat found during verification**: `is_public_domain` gates the *image*, not the *record's metadata license* — a live sample (`artworks/129884`, "Starry Night and the Astronauts" by Alma Thomas) has `is_public_domain: false` and an explicit `copyright_notice` ("© Estate of Alma Thomas..."), yet the API still returns a populated `image_id` and thumbnail for it. This means **an `image_id` being present does not by itself mean the image is reusable** — `is_public_domain` must be checked before treating any `image_id` as open access. Even when `is_public_domain: true`, the museum's policy caveats reuse: "Although the museum is not aware of and does not believe that such images are subject to any copyright restrictions, it is the sole responsibility of the image user to identify and obtain any necessary third-party permissions." Not all CC0-eligible images are necessarily available at full resolution/format — the docs point users to the separate image-licensing page for request paths on other images. License: metadata in the response is CC0 except the human-written `description` field, which is CC-BY 4.0 — "The `description` field in this response is licensed under a Creative Commons Attribution 4.0 Generic License (CC-By)... All other data in this response is licensed under... Creative Commons Zero (CC0)." Scale: "over 50,000 images... believed to be in the public domain" are open access, out of 100,000+ total artworks with metadata in the API. Images are served via IIIF Image API 2.0, e.g. `https://www.artic.edu/iiif/2/{image_id}/full/843,/0/default.jpg`. — http://api.artic.edu/docs/ (retrieved 2026-09-08, license_text/IIIF); response `info.license_text` (verified live) against `artworks/129884`; https://www.artic.edu/open-access (via indexed excerpt, direct fetch blocked, retrieved 2026-09-08, scale/caveat text).

- **Pagination mechanism**: `page` and `limit` query params. Default page size is 12 records; `limit` cannot exceed 100. A hard ceiling applies across pagination: "you cannot request more than 10,000 records from a single search query." Use the `fields` parameter to request only needed fields and reduce payload size. — http://api.artic.edu/docs/ (retrieved 2026-09-08).

- **Rate limits**: "Anonymous users are throttled to 60 requests per minute." No documented higher tier via API key (no key mechanism exists at all per the "no auth" statement above) — 60 req/min appears to be a flat ceiling for all callers, not just unauthenticated ones in a two-tier system, since the docs describe no authenticated path. — http://api.artic.edu/docs/ (retrieved 2026-09-08).

- **Caching guidance**: Explicit, unlike the Met: "Cache API responses in your system when possible." The docs also ask integrators to set a descriptive `AIC-User-Agent` header (app name + contact email) specifically so AIC can identify and contact heavy/misbehaving consumers — an implicit signal that caching is expected to reduce load rather than re-fetching per request. — http://api.artic.edu/docs/ (retrieved 2026-09-08).

- **Gaps / undocumented restrictions found during verification**:
  - The single api.artic.edu/docs page does not publish a full, canonical field list for `/artworks` (unlike the Met, which documents every field name) — the actual field set had to be partially reconstructed from a live sample request plus example snippets in the docs; an integration should not assume completeness of the field list captured here without a further live schema probe.
  - `is_public_domain: false` artworks still return an `image_id` and a full thumbnail object (confirmed live) — this is the single most important gotcha: naive code that renders any artwork with a non-null `image_id` will render copyrighted images without attribution/rights clearance. Must gate strictly on `is_public_domain === true`.
  - No documented distinction between "authenticated" and "anonymous" request rate limits was found — the docs describe only the anonymous 60 req/min figure and no authenticated path exists to escalate it, meaning 60 req/min is effectively a hard ceiling for all Phase 1 ingestion traffic and must be respected by a backoff/queue in any bulk-ingest job.
  - The 10,000-record cap on a single search query (same shape as the Met's 10,000-offset+limit cap) means true full-collection harvesting requires either the documented bulk data dump (linked from the docs site but not fetched/verified in this pass) or a filtered/sharded set of queries, not a single paginated crawl.

**Integration priority**: Phase 1 (primary ingestion source, alongside the Met — per Art Atlas product definition, Met + AIC are the only two Phase 1 collection sources).
